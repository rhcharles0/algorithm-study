# feedback

문제 폴더 하나를 받아 코드를 읽고 그 폴더의 `README.md`를 갱신한다.

## 입력

인자로 폴더 경로가 오면 그 폴더. 인자가 없으면 **가장 최근에 수정된 문제 폴더**를 쓴다:

```bash
ls -dt problems/*/*/ | head -1
```

## 절차

1. 대상 폴더의 모든 소스 파일(`*.java`, `*.cpp`, `*.py` 등)과 `README.md`를 읽는다.
2. 파일이 없거나 템플릿 그대로면 멈추고 사용자에게 알린다. 추측으로 채우지 않는다.
3. README.md 상단 표에서 비어 있는 칸(출처/문제번호/링크/난이도/카테고리/푼 날짜/언어)을 채운다.
   - 폴더 경로는 `problems/<출처>/<번호>` 다. 폴더명에 문제 이름이 없으니 **출처와 번호는 경로에서 그대로 가져온다.**
   - **출처는 반드시 채운다.** 폴더명(`programmers` `swea` `codetree` `leetcode` `baekjoon`)을 한국어 정식 명칭으로 적는다:
     `프로그래머스` / `SWEA` / `코드트리` / `LeetCode` / `백준`
   - **링크도 출처+번호로 만들어 채운다.** 비워 두지 않는다.
     - 프로그래머스 `https://school.programmers.co.kr/learn/courses/30/lessons/<번호>`
     - 코드트리 · 백준: URL 규칙이 없거나(코드트리) 서비스가 종료되어(백준) 링크는 `?` 로 두고 물어본다
     - LeetCode `https://leetcode.com/problems/<slug>/` — slug 는 README 제목에서 만든다
     - SWEA `https://swexpertacademy.com/main/code/problem/problemDetail.do?contestProbId=<번호>` (번호 체계가 달라 확실치 않으면 `?` 로 두고 물어본다)
   - 문제 이름은 폴더명에 없다. README 제목(`# <문제 이름>`)에서 가져오고, 제목이 아직 템플릿 그대로면 사용자에게 물어본다.
   - 난이도를 모르면 `?` 로 두고 물어본다. 추측해서 적지 않는다.
4. `---` 아래 영역을 **덮어쓴다** (위의 사용자 작성 영역은 건드리지 않는다).

## 채울 내용

### 카테고리
자료구조/알고리즘 태그를 붙인다. 예: `해시`, `우선순위 큐`, `DFS/BFS`, `DP - LIS`, `투 포인터`, `유니온 파인드`, `이분 탐색`.
그리고 README 표의 `관련 개념` 칸에 해당하는 `concepts/` 노트 경로를 상대경로 링크로 채운다.
- 예: `[heap](../../../concepts/data-structure/heap.md)`
- 노트 파일이 아직 없으면 링크는 그대로 적고 "아직 안 쓴 개념" 이라고 알려준다.
- 주제 목록은 `concepts/README.md` 참고.

### 복잡도
언어별로 한 줄씩. 입력 크기 변수를 명시한다 (`N = 배열 길이`, `M = 쿼리 수`).
- 시간: 루프 중첩, 정렬, 자료구조 연산 비용을 실제로 세서 산출한다. 어림짐작 금지.
- 공간: 입력 제외 추가 메모리.
- 문제의 입력 제한과 대조해 **통과 가능한지** 판정한다 (예: `N ≤ 10^5` 인데 O(N²) → 시간 초과 위험).

### 현재 풀이의 문제점
실제로 코드에 있는 것만 적는다. 없으면 "없음"이라고 쓴다. 볼 것:
- 불필요한 정렬/복사, 매 루프마다 재계산, `List.contains()` 같은 O(N) 조회
- Java: `Scanner` 대신 `BufferedReader`, 문자열 `+=` 루프, 오토박싱 남용
- C++: 불필요한 값 복사(참조 전달), `endl` 남발, `sync_with_stdio` 누락
- 오버플로우 (`int` vs `long`/`long long`), 네이밍, 중복 코드

### 다른 대안
더 나은 접근이 있으면 **복잡도 비교와 함께** 적는다. 없으면 "현재 풀이가 적절"이라고 쓴다.
대안이 코드로 3~4줄이면 스니펫을 같이 넣는다. 길면 접근법만 설명한다.

### 놓친 엣지 케이스
빈 입력, 원소 1개, 중복 값, 최대/최소 경계, 음수, 오버플로우 등 코드가 실제로 못 막는 것만.

## 규칙

- 한국어로 쓴다.
- 코드를 고치지 않는다. 피드백만 쓴다. 사용자가 고쳐달라고 하면 그때 고친다.
- 두 언어 풀이가 접근이 다르면 그 차이를 짚는다.
- 한쪽 언어 풀이만 있으면 나머지 언어 풀이를 권한다 (Java/C++ 둘 다 준비 중).
- 잘한 점은 한 줄이면 충분하다. 칭찬 문단 금지.
