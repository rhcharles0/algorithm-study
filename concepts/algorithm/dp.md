# 동적 계획법 (DP)

| 항목 | 내용 |
|---|---|
| 분류 | 알고리즘 |
| 관련 문제 | [PG 43165 타겟 넘버](../../problems/programmers/43165) |

## 한 줄 정의

**같은 부분 문제를 두 번 풀지 않도록 답을 적어두는** 기법.
완전탐색이 O(2ᴺ) 로 터질 때, 상태 수가 작으면 DP 로 내려온다.

## 언제 쓰나

- 완전탐색을 떠올렸는데 **N 이 20을 넘어** 2ᴺ 가 감당이 안 될 때
- **"경우의 수" / "최댓값" / "가능한가"** 를 묻는데 선택이 순차적일 때
- 같은 상태가 **여러 경로로 반복해서 등장**할 때

> **판별법**: 완전탐색 트리를 그렸을 때 **같은 `(인덱스, 누적값)` 이 여러 번 나오면** DP 다.
> 한 번씩만 나오면 DP 로 바꿔도 안 빨라진다.

DP 가 아닌 것: 상태가 계속 갈라지기만 하면([backtracking.md](backtracking.md)),
격자 최단거리면([dfs-bfs.md](dfs-bfs.md) BFS).

## 동작 원리

두 가지 방식이 있다. 결과는 같다.

| | 방식 | 장단점 |
|---|---|---|
| **탑다운** | 재귀 + 메모이제이션 | 완전탐색에서 캐시만 붙이면 됨. 스택 깊이 주의 |
| **바텀업** | 반복문 + 배열 | 빠르고 스택 안전. **점화식을 먼저 세워야** 쓸 수 있다 |

완전탐색 코드가 이미 있으면 **탑다운이 diff 가 가장 짧다.** 캐시 배열 하나 붙이면 끝이다.

## 대표 환원 — 부호 결정 → 부분집합 합

[PG 43165 타겟 넘버](../../problems/programmers/43165)가 교과서적인 예다.
각 원소에 `+`/`-` 를 붙여 `target` 을 만드는 경우의 수 → **완전탐색이면 O(2ᴺ)**.

`-` 를 붙일 원소들의 합을 `s` 라 하면

```
(전체합 - s) - s = target
→  s = (전체합 - target) / 2
```

문제가 **"합이 `s` 인 부분집합의 개수"** 로 바뀐다. 상태가 `s` 하나뿐이다.

```java
static int solve(int[] numbers, int target) {
    int sum = 0;
    for (int n : numbers) sum += n;
    if (target > sum || ((sum - target) & 1) == 1) return 0;   // 도달 불가 / 패리티 불일치
    int s = (sum - target) / 2;

    int[] dp = new int[s + 1];
    dp[0] = 1;                                   // 아무것도 안 고르면 합 0 — 1가지
    for (int n : numbers)
        for (int v = s; v >= n; v--)             // ← 역순
            dp[v] += dp[v - n];
    return dp[s];
}
```

| | 시간 | N=20, S=1000 |
|---|---|---|
| 완전탐색 | O(2ᴺ) | 1,048,576 |
| DP | O(N·S) | **10,000** |

**이 문제는 N ≤ 20 이라 완전탐색으로도 통과한다.** DP 를 익히는 이유는 속도가 아니라
**N 이 40이 되면 완전탐색만 즉사**하기 때문이다. 같은 문제가 N 을 키워 다시 나온다.

## ⚠ 정순 / 역순 — 한 글자로 문제가 바뀐다

위 코드의 `for (int v = s; v >= n; v--)` 에서 **역순이 핵심이다.**

```java
for (int v = s; v >= n; v--) dp[v] += dp[v - n];   // 0/1 — 각 원소 1번만
for (int v = n; v <= s; v++) dp[v] += dp[v - n];   // 무한 — 같은 원소 여러 번
```

역순이면 `dp[v - n]` 이 **이번 원소를 아직 안 쓴 값**이라 한 번만 쓰인다.
정순이면 방금 갱신된 값을 다시 참조해 **같은 원소를 중복 사용**한다.

실측 — `{1,2,3}` 으로 합 5 만들기:

| | 결과 | 의미 |
|---|---|---|
| 역순 | **1** | `{2,3}` 하나 |
| 정순 | **5** | `1+1+3`, `1+2+2`, … 중복 허용 |

> **0/1 배낭이면 역순, 무한 배낭이면 정순.** 외워라. 이 한 글자가 제일 많이 틀린다.

## 복잡도

| 형태 | 시간 | 공간 |
|---|---|---|
| 1차원 (부분집합 합, 배낭) | O(N·S) | O(S) |
| 2차원 (LCS, 편집거리) | O(N·M) | O(N·M) → 롤링으로 O(M) |
| LIS | O(N log N) (이분 탐색 병용) | O(N) |
| 비트마스크 DP (외판원 등) | O(2ᴺ·N²) | O(2ᴺ·N) — N ≤ 16 |

**상태 수 × 상태당 전이 비용**이 시간이다. 상태를 먼저 세어라.

## 구현 — 탑다운으로 바꾸는 최소 diff

완전탐색이 이미 있으면 캐시만 얹는다.

```java
static Integer[][] memo;                          // null = 아직 안 품

static int dfs(int idx, int acc) {
    if (idx == n) return acc == target ? 1 : 0;
    if (memo[idx][acc + OFFSET] != null) return memo[idx][acc + OFFSET];
    return memo[idx][acc + OFFSET] = dfs(idx + 1, acc) + dfs(idx + 1, acc - arr[idx] * 2);
}
```

`acc` 가 음수까지 가면 **`OFFSET` 을 더해 배열 인덱스로 만든다.** 이게 귀찮으면 바텀업이 짧다.

## 표준 라이브러리

| | Java | C++ |
|---|---|---|
| 캐시 배열 (미방문 구분) | `Integer[]` (null) 또는 `int[]` + `Arrays.fill(-1)` | `vector<int>` + `-1` |
| 2차원 초기화 | `for (int[] r : dp) Arrays.fill(r, -1);` | `vector<vector<int>> dp(n, vector<int>(m, -1))` |
| 큰 수 | `long` | `long long` |

`Integer[]` 는 오토박싱이 붙는다. 상태가 100만을 넘으면 `int[]` + `-1` 이 빠르다.

## 주의할 점

1. **정순/역순** — 0/1 이면 역순, 무한이면 정순 (위 ⚠).
2. **`dp[0] = 1`** 초기값을 빼먹으면 전부 0이 나온다. "아무것도 안 고른 경우 1가지"다.
3. **도달 불가·패리티를 먼저 거른다.** `target > sum` 이거나 `(sum - target)` 이 홀수면 답은 0인데,
   안 거르면 `s` 가 음수가 돼 배열 생성에서 터진다.
4. **음수 상태는 오프셋으로.** 배열 인덱스는 음수가 안 된다.
5. **오버플로우** — 경우의 수는 금방 커진다. 곱이 끼면 `long`.
6. **N ≤ 20 이면 DP 로 안 바꿔도 된다.** 완전탐색이 통과하면 그게 정답이다 — 짧고 덜 틀린다.
   DP 는 **터질 때 꺼내는 카드**다.
