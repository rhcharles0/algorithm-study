# 완전탐색 / 약수 열거

| 항목 | 내용 |
|---|---|
| 분류 | 알고리즘 |
| 관련 문제 | [PG 42842 카펫](../../problems/programmers/42842) |

## 한 줄 정의

**가능한 후보를 전부 만들어 보고 조건에 맞는 것을 고르는** 탐색.
"전부"의 범위를 얼마나 줄이느냐가 실력이다 — 줄이는 대표적인 도구가 **약수 열거**다.

## 언제 쓰나

- **답의 후보가 눈에 보이게 유한할 때.** 카펫의 세로 길이, 마름모 크기 K, 벽 3개의 위치
- 삼성 코테에서는 **"완전탐색으로 후보를 만들고 → 시뮬레이션으로 점수를 매긴다"** 가 기본형
- 가지치기가 들어가면 백트래킹 → [backtracking.md](backtracking.md)
- 각 원소를 넣/뺀다 2갈래면 DFS → [dfs-bfs.md](dfs-bfs.md)

**후보 수 × 한 후보당 비용**을 코드 쓰기 전에 곱해봐라. 1억이 넘으면 접근을 바꾼다.

## 탐색 범위를 줄이는 3가지

### 1. 제약이 진짜 상한을 정한다 — 겉보기에 속지 마라

[PG 42842 카펫](../../problems/programmers/42842)에서 `yellow ≤ 2,000,000` 만 보면
루프가 200만처럼 보인다. 그런데 `brown ≤ 5,000` 이 있다.

```
brown = 2(w + h) - 4 ≤ 5000   →   w + h ≤ 2502
h ≥ 3                         →   w ≤ 2499
```

**실제 상한은 2,499다.** 큰 제약이 아니라 **작은 제약이 상한을 정한다.**
두 변수가 식으로 묶여 있으면 항상 이걸 먼저 따져라.

### 2. 약수는 `√N` 까지만 보면 된다

`N = x * y` 인 약수쌍에서 **둘 중 하나는 반드시 `√N` 이하**다.
따라서 `i` 를 `√N` 까지만 돌면 모든 약수쌍을 얻는다.

```java
for (int i = 1; (long) i * i <= n; i++) {
    if (n % i != 0) continue;
    int j = n / i;          // i <= j 가 자동 보장된다
    process(i, j);
}
```

| | 반복 (N = 10⁶) |
|---|---|
| `i = 1 → N` | 1,000,000 |
| `i = 1 → √N` | **1,000** |

**덤으로 `i <= j` 정렬이 공짜다.** "가로 ≥ 세로" 같은 조건을 따로 처리할 필요가 없다.

> `i * i <= n` 에서 `i` 가 `int` 면 `n` 이 클 때 오버플로우한다. `(long) i * i` 로 쓰거나
> `i <= n / i` 를 써라.

### 3. 식으로 차원을 줄인다

변수 2개를 전부 돌리지 말고, 한쪽이 정해지면 나머지가 따라오는지 본다.

```
w * h = brown + yellow        ← 곱을 알고
w + h = (brown + 4) / 2       ← 합도 알면
```

`w, h` 는 `t² - St + P = 0` 의 두 근이라 **루프가 0이 된다.**
다만 `Math.sqrt` 오차 검증이 붙으니, 루프가 1,000회짜리면 그냥 돌리는 게 낫다.
**이 관계식을 아는 것 자체가 수확**이고, 탐색을 날려야 할 때 꺼내 쓴다.

## 경계를 어디서 시작할까

완전탐색 버그의 대부분은 **루프 시작점**에서 난다. 42842 에서 실제로 났던 것들:

| 실수 | 결과 |
|---|---|
| `x = yellow / 2` 부터 시작 | 정답 구간(`√yellow` 근처)을 **이미 지나침** |
| `x = 0` 부터 시작 | `yellow / x` → **0으로 나눔** |
| `y == 1` 을 스킵 | `yellow` 가 소수면 유일한 정답을 버림 |

> **의미 있는 최솟값부터 시작해라.** 카펫 세로는 "테두리 2줄 + 노란 1줄"이라 최소 3이다.
> 3부터 시작하면 0 나눗셈도, `y == 1` 예외도 **애초에 생기지 않는다.**
> 경계를 가드로 막는 것보다 **경계가 안 생기게 범위를 잡는 것**이 항상 낫다.

## 복잡도

| 형태 | 시간 |
|---|---|
| 1차원 전체 훑기 | O(N) |
| 약수 열거 | **O(√N)** |
| 격자 위 두 점 고르기 | O((N·M)²) — 50×50 이면 625만, 위험선 |
| 부분집합 | O(2ᴺ) — N ≤ 20 |
| 순열 | O(N!) — N ≤ 10 |

## 구현

```java
// 약수쌍 열거 — i <= j 보장
for (int i = 1; (long) i * i <= n; i++) {
    if (n % i != 0) continue;
    int j = n / i;
    // ...
}
```

```cpp
for (int i = 1; (long long) i * i <= n; i++) {
    if (n % i) continue;
    int j = n / i;
    // ...
}
```

## 주의할 점

1. **작은 제약이 상한을 정한다.** 큰 값만 보고 O(N) 을 겁내지 마라 (위 1번).
2. **`√N` 루프에서 등호를 빼먹지 마라.** `i * i <= n` 의 `=` 가 없으면 **정사각수를 통째로 놓친다**
   (42842 의 정사각형 카펫 `1251 x 1251`).
3. **`i * i` 오버플로우** — `(long) i * i` 또는 `i <= n / i`.
4. **경계를 가드로 막지 말고 범위로 피해라** (위 "경계를 어디서 시작할까").
5. **답을 못 찾으면 `null` 을 반환하지 마라.** 채점기에서 NPE 가 된다.
   "답이 항상 존재"하는 문제에서 못 찾았다면 로직 버그이므로 `throw` 가 원인을 빨리 알려준다.
6. **셀프 체크에 경계 케이스를 박아둬라.** 최소 입력·정사각형·가장 납작한 경우.
   `assert` 로 고정해두면 나중에 `<=` 를 `<` 로 바꾸는 실수가 즉시 잡힌다.

```java
// ✗ 배열은 참조 비교라 항상 false — 검증이 죽어 있다
assert solve(10, 2) == new int[]{4, 3};
// ✓
assert Arrays.equals(solve(10, 2), new int[]{4, 3});
```
