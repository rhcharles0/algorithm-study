## 문제 요약

1부터 N²까지의 수를 N×N 배열에 시계 방향 달팽이 모양으로 채워 출력한다. 첫 입력 T는 테스트 케이스 수이며, 각 케이스에는 N(1 ≤ N ≤ 10)이 주어진다. 각 결과는 `#t`를 먼저 출력한 뒤 배열을 행마다 공백으로 구분해 출력한다.

## 풀이 접근

1. `N×N` [배열](../../../concepts/data-structure/array.md) *(아직 안 쓴 노트)*의 첫 칸에 1을 기록하고, [큐](../../../concepts/data-structure/queue.md) *(아직 안 쓴 노트)*에 시작 좌표를 넣는다.
2. 위·오른쪽·아래·왼쪽 방향 배열을 만들고 오른쪽 방향에서 출발한다.
3. 큐에서 현재 좌표를 꺼내 다음 칸을 계산하며, 범위 밖이거나 이미 채운 칸이면 방향 인덱스를 한 칸 회전한다.
4. 다음 칸에 숫자를 기록하고 그 좌표를 큐에 넣는 과정을 `N²`까지 반복한다.
5. 테스트 케이스 번호와 완성한 배열을 `StringBuilder`에 모아 한 번에 출력한다.

## 복잡도

| 언어 | 시간 복잡도 | 공간 복잡도 |
|---|---|---|
| Java | 전체 O(Σ Nᵢ²) | O(max Nᵢ² + Σ Nᵢ²), 출력 버퍼 포함 |
| C++ | 미작성 (템플릿 그대로) | - |

`T`는 테스트 케이스 수, `Nᵢ`는 i번째 배열의 한 변 길이다. 한 케이스에서 숫자 기록은 `Nᵢ²−1`회, 출력 순회는 `Nᵢ²`회다. 큐에는 좌표 하나만 유지되므로 큐의 최대 공간은 O(1)이지만, 좌표 배열 객체는 케이스마다 총 O(Nᵢ²)개 생성한다. 결과 배열은 O(Nᵢ²), 모든 케이스의 출력을 누적하는 버퍼는 O(Σ Nᵢ²) 공간을 사용한다. `N ≤ 10`에서 케이스당 최대 100칸을 처리하므로 이 복잡도는 적절하다.

## 피드백

### 현재 풀이의 문제점

- 제출 풀이의 정답 오류는 발견하지 않았다. 이동할 때 다음 좌표를 큐에 넣으며, `N=1`은 이동 반복을 건너뛰고 1을 출력한다. 이전 피드백의 배열 범위 오류와 `NullPointerException` 주장은 잘못된 분석이었다.
- 큐에는 좌표가 하나만 들어가므로 행·열 변수로 충분하다. 현재 구현은 칸마다 `int[]`를 생성하는 비용이 추가된다.
- `Main.java`는 함수형 템플릿 그대로라 제출본에 없는 `solution(int[])`을 호출한다. 이 파일로는 현재 풀이를 검증할 수 없으며, 표준입력 제출본은 `java Solution.java < input.txt` 방식으로 실행해야 한다. SWEA 제출에 필요한 `main`은 적절하다.

### 다른 대안

- 방향 전환 방식은 적절하다. 큐 대신 현재 행·열 변수를 갱신하면 좌표 객체 생성을 없앨 수 있다. 케이스당 시간 O(N²), 배열 공간 O(N²)는 동일하다.

### 놓친 엣지 케이스

- 허용 범위에서 발견한 누락 없음. `N=1~10`을 한 번에 입력해 각 결과를 테두리부터 층별로 생성한 기대 배열과 비교했고 모두 일치했다. 최소 크기, 홀수 크기의 중앙 칸, 최대 크기, 여러 테스트 케이스 출력을 포함한다.
- 공식 예제 파일은 없어 공식 예제 대조와 온라인 채점 결과는 확인하지 않았다.
