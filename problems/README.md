# 삼성 SW 역량테스트 커리큘럼

**목표**: 삼성 코테 데뷔 · **현재**: 백준 골드1 경험 · **기간**: 8주 (주 5문제 기준 약 40문제)

## 삼성 코테는 뭐가 다른가

| | 일반 코테 (카카오 등) | 삼성 SW 역량테스트 |
|---|---|---|
| 문제 수 / 시간 | 5~7문제 / 5시간 | **2문제 / 3시간** |
| 채점 | 부분 점수 있음 | **전부 통과 아니면 0점** |
| 출제 유형 | 자료구조·알고리즘 폭넓게 | **시뮬레이션 · 완전탐색 · BFS 에 집중** |
| 요구 능력 | 알고리즘 선택 | **긴 요구사항을 틀리지 않고 구현하는 지구력** |

골드1을 풀어봤다면 **알고리즘 지식은 이미 충분하다.** 부족한 건 딱 두 가지다.

1. **구현 지구력** — 요구사항이 A4 한 장이고 단계가 5~6개인 문제를 한 번에 맞히는 능력
2. **디버깅 속도** — 부분 점수가 없어서, 틀린 원인을 20분 안에 찾아야 한다

그래서 이 커리큘럼은 **새 알고리즘을 배우는 게 아니라 기출 시뮬레이션을 반복**하는 구성이다.

---

## 자주 나오는 유형 (출제 비중순)

1. **격자 시뮬레이션** — 회전·이동·충돌·소멸. 삼성의 절반 이상
2. **완전탐색** — 순열/조합/백트래킹으로 모든 경우 만들고 시뮬레이션
3. **BFS** — 최단거리, 여러 시작점, 상태 추가된 BFS
4. **구현 + 자료구조** — 덱, 우선순위 큐를 쓰는 시뮬레이션

DP·그래프 이론(MST, 최단경로)·문자열 알고리즘은 **거의 안 나온다.** 여기에 시간 쓰지 마라.

## 삼성 문제에서 실제로 틀리는 이유

거의 이 다섯 가지다. 풀 때마다 의식적으로 점검해라.

1. **깊은 복사를 안 함** — 격자를 복사한 줄 알았는데 참조만 복사
   - Java: `arr.clone()` 은 2차원에서 **얕은 복사다.** 행마다 복사해야 한다
   - C++: `vector<vector<int>>` 는 대입이 값 복사 → 안전하지만 느릴 수 있다
2. **회전/이동 순서** — "동시에 이동" 인데 순차로 처리해서 결과가 달라짐. 새 배열에 쓰고 마지막에 교체
3. **방향 배열 순서** — 문제가 정한 우선순위(예: 위 → 왼쪽 → 아래 → 오른쪽)를 임의로 바꿈
4. **오버플로우** — Java `int` / C++ `int` 범위 초과. 곱셈 나오면 `long`
5. **종료 조건 누락** — "더 이상 변화가 없으면 종료" 를 빼먹고 무한 루프

## 풀기 전 30초 체크

- 격자 크기 N, 시간 T → **최악 연산 수**를 먼저 계산한다. `N⁴ × T` 가 1억 넘으면 다시 생각
- 요구사항의 **단계**를 번호로 적는다. 그대로 함수 이름이 된다 (`move()`, `merge()`, `spread()`)
- 예제가 2개 이상이면 **둘 다** 손으로 돌려본다. 1개만 맞고 2개째 틀리는 게 제일 흔하다

## 언어 전략

**본선은 Java 로 친다.** C++ 는 Phase 2 까지만 병행하고, Phase 3 부터는 Java 에 집중해라.
두 언어를 끝까지 병행하면 문제 수가 반으로 준다 — 삼성은 문제 수가 곧 실력이다.

| | Java | C++ |
|---|---|---|
| 격자 복사 | `for (int i=0;i<n;i++) b[i]=a[i].clone();` | `b = a;` |
| 덱 | `ArrayDeque<int[]>` | `deque<array<int,2>>` |
| 우선순위 큐 | `PriorityQueue<>(Comparator.comparingInt(...))` | `priority_queue<T, vector<T>, greater<>>` |
| 입력 | `BufferedReader` + `StringTokenizer` | `cin` + `sync_with_stdio(false)` |
