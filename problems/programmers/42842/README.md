## 문제 요약

가운데는 노란색, **테두리 1줄만 갈색**인 직사각형 격자 카펫이 있다.
갈색 격자 수 `brown` 과 노란색 격자 수 `yellow` 가 주어질 때 카펫의 `[가로, 세로]` 를 구한다 (가로 ≥ 세로).

- `brown`: **8 ~ 5,000**
- `yellow`: **1 ~ 2,000,000**
- 답이 존재하는 입력만 주어진다.

핵심 관계식 두 개 — 가로 `w`, 세로 `h` 라 할 때
`w * h = brown + yellow` 이고 `(w-2) * (h-2) = yellow` (= `2*(w+h) - 4 = brown`).

## 풀이 접근

카펫 전체 칸 수 `total = brown + yellow` 가 `가로 * 세로` 라는 점을 이용해,
**`total` 의 약수쌍을 작은 변부터 훑는 완전탐색**으로 접근했다.

1. `height` 를 3부터 `height * height <= total` 까지 증가시킨다.
   세로 최솟값이 3인 이유는 테두리 위아래 2줄 + 노란 1줄이 최소 구성이기 때문이다.
2. `total % height != 0` 이면 약수가 아니므로 건너뛴다.
3. `width = total / height` 로 짝을 만든다. `height <= √total` 이므로
   **`height <= width` 가 자동으로 보장돼 가로 ≥ 세로 정렬을 따로 하지 않는다.**
4. 테두리를 벗긴 안쪽 `(width-2) * (height-2)` 가 `yellow` 와 같으면 `{width, height}` 를 반환한다.
5. 끝까지 못 찾으면 `IllegalStateException` 을 던진다 — 답이 항상 존재하는 문제이므로
   여기 도달했다는 건 로직 버그라는 뜻이다.

## 복잡도

`B = brown ≤ 5,000`, `Y = yellow ≤ 2,000,000`, `T = B + Y` (카펫 전체 칸 수)

| 언어 | 시간 복잡도 | 공간 복잡도 |
|---|---|---|
| Java | **O(√T)** — `height = 3 → √T`. 제약 내 최악 **1,249회** | O(1) |
| C++ | **미구현** (템플릿 그대로) | — |

`T` 의 상한은 `Y` 가 아니라 `B` 가 정한다: `brown = 2(w+h) - 4 ≤ 5000` → `w + h ≤ 2502`,
`h ≥ 3` → `w ≤ 2499`. 가장 큰 카펫은 정사각형 `1251 x 1251` 이고 이때 `T = 1,565,001`, `√T = 1251`.

**통과 판정: 여유롭게 통과.** 반복 1,249회면 제한 시간의 근처에도 못 간다.

> **제약 내 전수 검증 통과.** `w ≥ h ≥ 3`, `brown ∈ [8,5000]`, `yellow ∈ [1,2·10⁶]` 를 만족하는
> 유효 카펫 **1,560,001 케이스 전부**를 돌려 오답 0개, 최악 반복 1,249회를 확인했다.

### 다른 대안

**A. 이차방정식으로 O(1) — 알아둘 가치는 있지만 제출은 지금 코드로**

지금 코드는 매 `height` 마다 `total % height` 를 물어보는데, 사실 **가로와 세로의 합은 이미 정해져 있다.**

```
(w-2)(h-2) = yellow
→ wh - 2(w+h) + 4 = yellow
→ total - 2(w+h) + 4 = yellow          (wh = total)
→ w + h = (brown + 4) / 2
```

합 `S = (brown+4)/2` 와 곱 `P = brown + yellow` 를 알면 `w, h` 는 `t² - St + P = 0` 의 두 근이다.

```java
int s = (brown + 4) / 2, p = brown + yellow;
int d = (int) Math.round(Math.sqrt((long) s * s - 4L * p));   // d = w - h
return new int[]{(s + d) / 2, (s - d) / 2};
```

| | 반복 |
|---|---|
| 현재 (약수 열거) | 1,249 |
| 대안 A (근의 공식) | 0 |

**그런데도 현재 코드를 권한다.** `Math.sqrt` 부동소수점 오차 때문에 `d*d == s*s - 4*p` 재확인이
필요하고, `s*s` 는 `long` 캐스팅을 빠뜨리면 조용히 넘친다. 1,249회를 없애자고 질 위험이 아니다.
**"합과 곱을 알면 근이 나온다"는 관계식 자체가 수확이다** — 다른 문제에서 탐색 자체를 날릴 때가 온다.

**B. C++ 풀이 — 아직 없다**

`solution.cpp` 이 템플릿 그대로다. STL 관용구로 옮기면 반환형이 `vector<int>` 로 바뀌는 게 전부다.
`return {width, height};` 처럼 중괄호 초기화로 바로 반환할 수 있다는 것,
Java 의 `new int[]{...}` 대비 이 부분이 어떻게 달라지는지를 직접 써 보는 게 이 레포의 목표다.

### 놓친 엣지 케이스

**없다.** 제약 내 유효 입력 1,560,001개 전수 검증에서 오답 0개다. 확인한 경계:

| 케이스 | 값 | 왜 위험한가 | 결과 |
|---|---|---|---|
| **최소 카펫** | `brown=8, yellow=1` → `[3,3]` | `height` 를 1이나 2부터 돌면 `(w-2)(h-2)` 가 0·음수가 된다 | ✅ `assert` 로 고정 |
| **`yellow` 가 소수** | `brown=10, yellow=2` → `[4,3]` | 안쪽이 `n x 1` 뿐이라 세로 하한에 딱 걸린다 | ✅ |
| **정사각형 카펫** | `brown=5000, yellow=1560001` → `[1251,1251]` | `height*height <= total` 의 **등호가 빠지면 놓친다** | ✅ `assert` 로 고정 |
| **가장 납작한 카펫** | `brown=5000, yellow=2497` → `[2499,3]` | 세로 하한 3에 정확히 걸리는 입력 | ✅ `assert` 로 고정 |
| **오버플로우** | `height*height`, `(w-2)*(h-2)` ≤ 1,565,001 | `int` 상한 2³¹ 대비 세 자릿수 여유 | ✅ 안전 |

경계 3개를 `assert` 로 박아둔 덕에, 이후 이 코드를 건드려 `<=` 를 `<` 로 바꾸는 식의 실수는
실행 즉시 잡힌다. **이게 `Arrays.equals` 로 고친 것의 실제 수익이다.**
