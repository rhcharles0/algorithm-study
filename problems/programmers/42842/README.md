## 문제 요약

가운데는 노란색, **테두리 1줄만 갈색**인 직사각형 격자 카펫이 있다.
갈색 격자 수 `brown` 과 노란색 격자 수 `yellow` 가 주어질 때 카펫의 `[가로, 세로]` 를 구한다 (가로 ≥ 세로).

- `brown`: **8 ~ 5,000**
- `yellow`: **1 ~ 2,000,000**
- 답이 존재하는 입력만 주어진다.

핵심 관계식 두 개 — 가로 `w`, 세로 `h` 라 할 때
`w * h = brown + yellow` 이고 `(w-2) * (h-2) = yellow` (= `2*(w+h) - 4 = brown`).

## 풀이 접근

노란색 영역을 `x * y` 직사각형으로 보고, **`yellow` 의 약수쌍을 전부 훑는 완전탐색**으로 접근했다.

1. `makeYellowTile(yellow, brown)` 에서 `x` 를 1부터 `yellow` 까지 증가시킨다.
2. `y = yellow / x` 로 짝을 만들고, `x*y != yellow` (약수가 아님)이거나 `y > x`
   (가로 ≥ 세로 위반)이면 건너뛴다.
3. 노란 영역 둘레에 1줄씩 두르면 카펫은 `(x+2) * (y+2)` 이므로,
   이 값이 **전체 칸 수 `brown + yellow`** 와 같으면 `{x+2, y+2}` 를 반환한다.
4. `yellow == 0` 가드를 앞에 두고, 끝까지 못 찾으면 `null` 을 반환한다.

## 복잡도

`B = brown ≤ 5,000`, `Y = yellow ≤ 2,000,000`, `W = 카펫 가로`

| 언어 | 시간 복잡도 | 공간 복잡도 |
|---|---|---|
| Java | **O(W)** — `x = 1 → W-2` 에서 답을 찾고 즉시 반환. 제약 내 최악 **2,497회** | O(1) |
| C++ | **미구현** (템플릿 그대로) | — |

겉보기엔 `x <= yellow` 라 O(Y) = 200만처럼 보이지만, 실제 상한은 `brown` 이 눌러준다:
`brown = 2(w+h) - 4 ≤ 5000` → `w + h ≤ 2502`, `h ≥ 3` → **`w ≤ 2499`**.
답을 찾는 즉시 반환하므로 반복은 `w - 2 ≤ 2497` 번을 넘지 않는다.

**통과 판정: 여유롭게 통과.**

> **제약 내 전수 검증 통과.** `w ≥ h ≥ 3`, `brown ∈ [8,5000]`, `yellow ∈ [1,2·10⁶]` 를 만족하는
> 모든 카펫(약 78만 쌍)을 돌려 **오답 0개**, 최악 반복 2,497회(카펫 `2499 x 3`)를 확인했다.
> 지난 피드백에서 지적한 버그 4개(판정식 `brown` → `brown+yellow`, `x` 시작점, `y == 1` 스킵,
> 0 나눗셈)는 전부 해결됐다.

## 피드백

### 현재 풀이의 문제점

로직은 맞다. 남은 건 전부 군더더기다.

**1. `assert` 가 배열을 `==` 로 비교한다 — 검증이 여전히 작동하지 않는다**

```java
assert solve(10, 2) == new int[]{4,3} : "sample 1";
```

`int[] == int[]` 는 **참조 비교**라 항상 `false` 다. `-ea` 로 돌리면 코드가 맞든 틀리든
`sample 1` 에서 터지고, `-ea` 없이 돌리면 아무것도 검사하지 않는다.
**지난번 버그 4개가 안 잡힌 이유가 이것이다.** 셀프 체크가 죽어 있으면 없는 것만 못하다.

```java
assert Arrays.equals(solve(10, 2), new int[]{4,3}) : "sample 1";
```

**2. `x` 를 1부터 시작하는데, 앞 절반은 전부 `continue` 로 버려진다**

```java
for(int x = 1; x <= yellow; x++){
    int y = yellow/x;
    if(y > x || x*y != yellow) continue;
```

`y > x` 는 곧 `x < √yellow` 라는 뜻이다. `yellow = 1,560,001` 이면 **x가 1249에 닿을 때까지
1,248번을 헛돈다.** 작은 쪽(`y`)을 `1 → √yellow` 로 돌리면 같은 약수쌍을 절반의 반복으로 훑는다.

**3. `if(yellow == 0) return null;` 은 죽은 코드다**

제한사항이 `yellow ≥ 1` 이라 들어올 수 없는 입력이다. 설령 0이 와도 `x <= 0` 이라
루프가 한 번도 안 돌고 그대로 `null` 이 나온다 — **가드가 있으나 없으나 결과가 같다.**
지난번 `/ by zero` 는 `x` 가 0에서 시작한 게 원인이었고, 그건 `x = 1` 로 이미 해결됐다.

**4. 못 찾으면 `null` 을 반환한다**

프로그래머스 채점기는 반환 배열에 바로 접근하므로 `NullPointerException` 이 된다.
문제가 "답이 항상 존재"를 보장하니 `null` 이 나왔다는 건 로직 버그라는 뜻이다.
`throw new IllegalStateException(...)` 이 원인을 훨씬 빨리 알려준다.

**5. `static public` — 수식어 순서가 뒤집혔다**

컴파일은 되지만 Java 관례는 `public static` 이다. 애초에 `solve` 에서만 부르는 내부 헬퍼라
`public` 자체가 불필요하다 → `private static`.

**6. 인자 순서가 뒤집혀 있다**

`solve(brown, yellow)` 인데 `makeYellowTile(yellow, brown)` 으로 넘긴다.
`(int, int)` 라 컴파일러가 안 잡아주는 자리다. **한쪽으로 통일해라.**

**7. `x`, `y` 라는 이름이 좌표처럼 읽힌다**

실제로는 "노란 영역의 가로/세로"다. `innerW`, `innerH` 면 `+2` 가 무슨 뜻인지 바로 보인다.

### 다른 대안

**A. 카펫 전체 칸 수의 약수를 √까지만 훑기 (권장)**

노란 영역 대신 **카펫 전체**를 기준으로 잡으면 식이 하나로 줄고, 작은 변부터 돌아
낭비 구간이 사라진다.

```java
static int[] solve(int brown, int yellow) {
    int total = brown + yellow;              // = w * h
    for (int h = 3; h * h <= total; h++) {   // 세로 최소 3 (테두리 2줄 + 노란 1줄)
        if (total % h != 0) continue;
        int w = total / h;                   // h <= w 자동 보장
        if ((w - 2) * (h - 2) == yellow) return new int[]{w, h};
    }
    throw new IllegalStateException("no carpet: brown=" + brown + ", yellow=" + yellow);
}
```

- `h <= √total` 이라 **가로 ≥ 세로 정렬이 공짜**다 (`y > x` 체크가 필요 없다).
- `h` 가 3부터라 0 나눗셈·`y==1` 같은 경계가 애초에 안 생긴다.
- 헬퍼 메서드가 사라져 **인자 순서 뒤집힘(6번)도 같이 없어진다.**

| | 최악 반복 (제약 내) |
|---|---|
| 현재 풀이 | 2,497 (`2499 x 3`) |
| 대안 A | 1,251 (`√total`) |

속도 차이는 체감이 없다. **얻는 건 경계 조건이 통째로 사라진다는 것**이고, 그게 지난번 버그 4개가
났던 자리다.

**B. 이차방정식으로 O(1)**

`w + h = (brown + 4) / 2 = S`, `w * h = brown + yellow = P` 이므로 `w, h` 는 `t² - St + P = 0` 의 두 근이다.

```java
int s = (brown + 4) / 2, p = brown + yellow;
int d = (int) Math.round(Math.sqrt((long) s * s - 4L * p));
return new int[]{(s + d) / 2, (s - d) / 2};
```

루프가 사라지지만 `Math.sqrt` 부동소수점 오차 때문에 `d*d == s*s - 4*p` 재확인이 필요하다.
1,251회짜리 루프를 없애자고 그 위험을 지는 건 손해다. **"합과 곱을 알면 근이 나온다"는 패턴만
기억해 두고, 제출은 A로 해라.**

**C. C++ 풀이 — 아직 없다**

`solution.cpp` 이 템플릿 그대로다. Java ↔ STL 대응이 목표니 반환형만 `vector<int>` 로 바꾸면 된다:

```cpp
vector<int> solution(int brown, int yellow) {
    int total = brown + yellow;
    for (int h = 3; h * h <= total; h++)
        if (total % h == 0 && (total / h - 2) * (h - 2) == yellow)
            return {total / h, h};
    return {};
}
```

### 놓친 엣지 케이스

**제약 내에서 코드가 틀리는 케이스는 없다** (전수 검증 완료). 확인한 경계:

| 케이스 | 값 | 결과 |
|---|---|---|
| **최소 카펫** | `brown=8, yellow=1` → `[3,3]` | ✅ `x=1, y=1` 에서 바로 잡힘 |
| **`yellow` 가 소수** | `brown=10, yellow=2` → `[4,3]` | ✅ `y == 1` 스킵을 없앤 덕 |
| **정사각형 카펫** | `brown=5000, yellow=1560001` → `[1251,1251]` | ✅ `y > x` 가 `>` 라 `x==y` 통과 |
| **가장 납작한 카펫** | `brown=5000, yellow=2497` → `[2499,3]` | ✅ 최악 반복 2,497회 |
| **오버플로우** | `x*y`, `(y+2)*(x+2)` ≤ 1,565,001 | ✅ `int` 안전. 대안 B의 `s*s` 만 `long` 필요 |

⚠️ 단, **`y > x` 의 `>` 가 `>=` 였다면 정사각형 카펫이 전부 오답이 된다.** 지금은 맞지만
이런 자리는 한 글자로 뒤집히니, 정사각형 케이스를 셀프 체크에 넣어 두는 습관을 들여라
(1번을 고치면 바로 할 수 있다).

### 잘한 점

지난 피드백의 버그 4개를 전부 정확히 짚어 고쳤다. `y > x` 로 가로 ≥ 세로를 거르는 방식도 맞다.
