## 문제 요약

`n × m` 격자에서 좌측 상단에서 우측 하단까지 이동할 때 지나야 하는 칸 수의 최솟값을 구한다. `1`은 이동 가능, `0`은 벽이며 상하좌우로 한 칸씩 움직인다. `1 ≤ n, m ≤ 100`이고 `(n, m) = (1, 1)`은 주어지지 않으며, 도달할 수 없으면 `-1`을 반환한다.

## 풀이 접근

Java 풀이는 이동 가능한 시작점 `(0, 0)`을 큐에 넣고 [BFS](../../../concepts/algorithm/dfs-bfs.md)를 수행한다. 상하좌우 이웃 중 격자 안에 있고 길이며 아직 방문하지 않은 칸을 큐에 넣으면서, 시작 칸을 1로 두고 `visited`에 지나온 칸 수를 기록한다. 탐색이 끝난 뒤 도착 칸의 값이 0이면 `-1`, 아니면 그 값을 반환한다.

## 복잡도

`N = maps.length`, `M = maps[0].length`.

| 언어 | 시간 복잡도 | 공간 복잡도 |
|---|---|---|
| Java | O(N·M): 각 칸은 최대 한 번 큐에 들어가고, 각 칸에서 4방향을 확인한다. `N, M ≤ 100`이므로 충분하다. | O(N·M): `visited`와 큐가 최악에 모든 칸을 저장한다. |
| C++ | 미작성 (템플릿 그대로) | - |

## 피드백

### 현재 풀이의 문제점
- `N`, `M`은 행·열을 뜻하는 이름으로 바꾸면 의도가 더 잘 드러난다.
- 각 칸을 큐에 넣을 때 `int[]` 좌표 객체를 하나씩 만들고, 호출 때마다 방향 배열도 만든다. 제한이 `100 × 100`이라 실제 성능 문제는 아니다.
- `answer`는 도착 칸 값을 담아 반환하는 용도로만 쓰여 바로 반환할 수 있다.

### 다른 대안
- 현재 BFS가 적절하다. 도착 칸을 큐에서 꺼냈을 때 바로 반환하면 도착 이후의 탐색을 줄일 수 있지만, 최악 시간 복잡도는 여전히 O(N·M)이다.

```java
if (cy == N - 1 && cx == M - 1) return visited[cy][cx];
```

### 놓친 엣지 케이스
- 문제의 입력 제한 안에서 놓친 엣지 케이스는 없다. 시작 칸이 벽이거나 도착 칸이 벽인 경우, 경로가 없는 경우는 모두 `-1`을 반환한다. 한 행 또는 한 열인 격자도 처리하며, `1 × 1` 격자는 입력으로 주어지지 않는다.
