## 문제 요약

숫자 한 자리가 적힌 종이 조각들(`numbers`)이 주어질 때, 조각을 **일부만 골라 임의 순서로 이어 붙여**
만들 수 있는 **서로 다른 소수의 개수**를 구한다. `011` 과 `11` 은 같은 수로 친다.

- `numbers` 길이: **1 ~ 7**, 0~9 문자로만 구성
- 예: `"17"` → `7, 17, 71` 이므로 3 / `"011"` → `11, 101` 이므로 2

## 풀이 접근

조각 수가 최대 7개라 **만들 수 있는 모든 수를 전부 만들어보는 완전탐색**으로 접근했다.

1. `visited` 를 **비트마스크 `int`** 로 두고, 각 조각을 썼는지를 비트로 관리한다.
2. `recur` 에서 아직 안 쓴 조각 `next` 마다 두 갈래로 재귀한다 —
   그 조각을 **건너뛰는** 분기와, `res * 10 + 숫자` 로 **뒤에 이어 붙이는** 분기.
   (일부만 골라 쓰는 경우를 커버하려는 의도)
3. 재귀에 들어올 때마다 현재까지 만든 `res` 를 `isPrime` 으로 검사하고,
   소수면 `primeSet`(`HashSet`)에 넣는다. `011` 과 `11` 처럼 **같은 값이 여러 경로로 나오는 중복은
   HashSet 이 걸러준다.**
4. `isPrime` 은 2와 짝수를 먼저 쳐내고 `i*i <= num` 까지 시험 나눗셈한다.
5. 최종 답은 `primeSet.size()`.

## 복잡도

N = `numbers.length()` (문제 제약: 1 ≤ N ≤ 7), M = 만들 수 있는 수의 최댓값 ≤ 10ᴺ

| 언어 | 시간 복잡도 | 공간 복잡도 |
|---|---|---|
| Java | O( Σₖ P(N,k)·2ᵏ · √M ) — N=7 일 때 재귀 **1,063,623회**, 실측 **39ms** | O(N) 재귀 스택 + O(결과 소수 개수) HashSet |
| C++ | **미구현** (템플릿 그대로) | — |

**통과 판정: 여유롭게 통과.** N ≤ 7 이라 최악에도 40ms 미만이다.
다만 아래 1번 때문에 필요한 탐색량의 **약 78배**를 돌고 있다.

## 피드백

### 현재 풀이의 문제점

**1. `recur` 의 "건너뛰기" 분기가 순수 중복이다 — 탐색량 78배**

```java
recur(str, next, res,                       visited | 1 << next);  // ← 이 줄
recur(str, next, res*10 + str.charAt(next) -'0', visited | 1 << next);
```

첫 줄은 `next` 를 **쓰지 않으면서 방문 처리만** 한다. 그런데 "안 쓴다"는 선택은
애초에 그 인덱스를 고르지 않으면 되는 것이라, 같은 숫자를 여러 경로로 중복 생성한다.
`HashSet` 이 중복을 지워주니 답은 맞지만, 탐색 자체가 낭비다.

| | 재귀 호출 수 (N=7) | 실측 |
|---|---|---|
| 현재 (skip 분기 있음) | 1,063,623 | 39ms |
| skip 분기 제거 | 13,700 | 2.6ms |

두 버전 모두 `"1234567"` → 1336, `"9999999"` → 0, `"1111111"` → 1 로 **답은 동일**하다.

**2. static 필드에 의존한다**

`primeSet.clear()` 를 넣어서 지금은 맞지만, static 상태는 구조적으로 위험하다.
프로그래머스 채점기는 **한 JVM에서 여러 테스트케이스를 연속 호출**하므로,
새 static 필드를 추가할 때마다 초기화를 잊으면 그대로 오답이 된다.

**3. `idx` 파라미터가 불필요하다**

```java
if(!(idx == -1 || res == 0) && isPrime(res))
```
`idx` 는 오직 "최초 호출인가"를 구분하는 데만 쓰인다. 그런데 최초 호출은 `res == 0` 이고
`isPrime(0)` 은 어차피 `false` 다. → `if (res > 0 && isPrime(res))` 한 줄이면 충분하고,
파라미터 하나가 사라진다.

**4. `isPrime` 이 짝수를 다시 나눈다**

```java
for(int i = 2 ; i *i <= num ; i++)
```
위에서 `num % 2 == 0` 을 이미 걸렀으므로 짝수 `i` 로 나누는 건 전부 헛수고다.
`for (int i = 3; (long)i*i <= num; i += 2)` 로 절반이 준다.

**5. `answer` 지역 변수가 불필요하다**

```java
int answer = 0;
...
answer = primeSet.size();
return answer;
```
→ `return primeSet.size();`

**6. `str` 만 파라미터, `end` 는 static — 일관성이 없다**

둘 다 재귀 내내 안 변하는 값이다. 하나로 통일하는 게 읽기 쉽다.

### 다른 대안

**A. skip 분기 제거 (권장, 1~3번 동시 해결)**

```java
static void recur(String s, int res, int visited) {
    if (res > 0 && isPrime(res)) primeSet.add(res);
    for (int i = 0; i < s.length(); i++) {
        if ((visited & (1 << i)) != 0) continue;
        recur(s, res * 10 + s.charAt(i) - '0', visited | 1 << i);
    }
}
```

중간 단계의 `res` 가 전부 검사 대상이므로 **부분집합을 따로 만들 필요가 없다.**
"1자리 → 2자리 → …" 가 자연스럽게 전부 커버된다. 재귀 1,063,623회 → 13,700회.

**B. 에라토스테네스 체 — 이 문제에선 비추천**

10⁷ 까지 체를 만들면 `isPrime` 이 O(1) 이 되지만, 전처리 10⁷ + 메모리 10MB 가
탐색량(1.4만) 대비 과하다. **A 를 적용하면 소수 판정 호출 자체가 1.4만 번**이라
현재 방식으로 충분하다.

> 판단 기준: 판정 횟수가 상한(10⁷)에 비해 훨씬 적으면 개별 판정, 비슷하거나 많으면 체.

**C. Java 표준 라이브러리**

`BigInteger.valueOf(res).isProbablePrime(20)` 도 있지만, 직접 짠 `isPrime` 보다 느리고
코테에서 얻는 게 없다. 지금 구현이 맞다.

### 놓친 엣지 케이스

실제로 돌려봤을 때 **현재 코드가 틀리는 케이스는 없다.** 확인한 것:

| 입력 | 기대 | 결과 |
|---|---|---|
| `"17"` | 3 | ✅ |
| `"011"` (앞자리 0) | 2 | ✅ `01` → 1 로 정규화됨 |
| `"0"` | 0 | ✅ `res == 0` 가드 |
| `"1111111"` (중복 숫자) | 1 | ✅ HashSet 이 처리 |
| `"9999999"` (최댓값) | 0 | ✅ 10⁷ < 2³¹, int 안전 |

다만 **`int` 안전은 N ≤ 7 이라는 제약에 기대고 있다.** N 이 10이 되면 10¹⁰ 로 넘쳐서
조용히 음수가 된다. 이런 문제에서는 제약을 확인하고 넘어가는 습관을 들여라.
